# 图谱如何嵌入市级集运（一页速览）

> 适用对象：数据架构师 / 业务产品经理 / 政府信息化负责人  
> 阅读时间：≈ 3 分钟

---

## 1. 核心命题

市级集运网络天然具备"节点—线路—业务"三重结构，与知识图谱的"实体—关系—属性"同构。将集运数据骨架升级为**图谱增强型**，可在不推翻现有系统的前提下，通过三层插拔实现语义升维。

---

## 2. 可插拔应用场景

### 场景 A：Rank 校验溯源

**痛点**：枢纽/站点等级评分（Rank）来源不透明，人工复核成本高，易出现"评分黑箱"。

**图谱嵌入方式**：
- 每个 `:LogisticsNode` 绑定 `:hasEvidence` 指向 `:RankEvidence`
- 证据链上链图谱，支持多源交叉验证（政府评级、吞吐量、客户投诉率）
- 评分变更自动触发溯源查询，输出可审计的 `provenance` 数组

**一句话价值**：任何 Rank 变动皆可追问"依据何来、由谁录入、何时生效"。

```sparql
# 示例：追溯 Hub-A 的评分依据
SELECT ?evidence ?source WHERE {
  sjy:Node_Hub_A sjy:hasEvidence ?evidence .
  ?evidence sjy:sourceUrl ?source .
}
```

---

### 场景 B：方言语义归一

**痛点**：不同区县、不同承运商对同一物流概念称呼各异（如"漕帮""水路帮""河运线"），导致数据汇聚时同义异名、统计失真。

**图谱嵌入方式**：
- 建立 `:DialectTerm` 方言词节点，通过 `:normalizedTo` 映射至标准 SKOS 概念
- 数据入仓时先过"方言消歧层"，将地方表述转写为图谱标准实体
- 支持增量学习：新方言词人工标注后自动补入 `rules/dialect_dict.json`

**一句话价值**：让系统"听懂"地方话，实现跨区域的语义级数据对齐。

```json
// 示例：方言映射片段
{
  "term": "漕帮",
  "region": "江南片区",
  "normalized": "inland-waterway-transport",
  "confidence": 0.97
}
```

---

### 场景 C：专利知识关联

**痛点**：集运网络升级依赖设备/工艺/算法创新，但专利知识与实际运营节点脱节，技术引进缺乏精准匹配。

**图谱嵌入方式**：
- `:PatentKnowledge` 作为知识单元节点，与 `:LogisticsNode` 通过 `:relatesToPatent` 关联
- 当节点发生设备更新或工艺改造时，自动检索关联专利族，生成技术推荐报告
- 支持按技术功效（降本/增效/低碳）多维过滤

**一句话价值**：把沉默的专利数据变成可运营的"技术导航仪"。

```yaml
# 示例：专利关联触发配置
plugin: patent_knowledge_link
trigger:
  event: node.equipment.updated
  action: |
    MATCH (n:LogisticsNode)-[:relatesToPatent]->(p:PatentKnowledge)
    WHERE p.techEffect CONTAINS "降本"
    RETURN p.title, p.patentNo, p.relevanceScore
```

## 3. 实施路径（四步启动）

| 步骤 | 动作 | 周期 |
|------|------|------|
| ① 建骨架 | 搭建 `data/rules/graph/nav` 四层目录，导入现有站点/线路清单 | 1 周 |
| ② 定本体 | 基于 `model.ttl` 扩展本地专属类与属性（如区县特色节点类型） | 1 周 |
| ③ 接插件 | 按需启用 Rank 溯源 / 方言归一 / 专利关联，配置 `registry.yml` | 2 周 |
| ④ 跑闭环 | 数据变更 → 图谱更新 → 推理触发 → 业务反馈，形成正向循环 | 持续 |

---

## 4. 关键设计原则

1. **同构映射**：不另起炉灶，现有关系型数据通过 ETL 直接映射为图谱三元组。
2. **插件自治**：三个场景独立开关，互不影响，支持灰度上线。
3. **溯源优先**：所有评分、归一、推荐操作均留痕，满足政务数据审计要求。
4. **方言友好**：把方言视为一等公民，而非脏数据；归一过程透明可干预。
